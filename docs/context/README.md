# Context folder

The working memory of this project. Anyone, or any assistant, picking up work
reads these files first.

| File                   | What it holds                                                     |
| ---------------------- | ----------------------------------------------------------------- |
| `RULES.md`             | How work is done here. Read first.                                |
| `PRODUCT.md`           | What the product is, who uses it, the screens, the business rules |
| `ARCHITECTURE.md`      | Stack, folders, boundaries, shared primitives, checks             |
| `DATA_MODEL.md`        | Tables, tenancy, access rules, database behaviour                 |
| `CURRENT_WORK.md`      | What is in flight, waiting, finished, parked                      |
| `DECISIONS.md`         | Settled choices, with dates and reasons                           |
| `templates/INITIAL.md` | Brief template for a new piece of work                            |
| `templates/PLAN.md`    | Plan template, filled in before code                              |
| `work/`                | One brief and plan per piece of work                              |

These are living documents. If a change makes something here untrue, fix it in
the same change.

Related: `docs/build-standards/` for the release standard,
`docs/ui-design/` for screen specifications and the design language,
`docs/ui-components/COMPONENT_MAP.md` for the component inventory.
