# Acceptance checklist

## Identity and consistency

- [ ] Text-only uppercase STARTWEB; no adjacent square logo.
- [ ] Solid blue shared sidebar, correct page selected, coherent grouped navigation.
- [ ] Central tokens, consistent type scale, spacing, radii and outline icons.
- [ ] One primary action per decision area; repeated instructions removed.
- [ ] No archived white-sidebar styling or unadapted demo branding.

## Pages and data

- [ ] All ten specified current pages work with live records and honest empty states.
- [ ] Settings remains reachable; sign-in uses its existing route.
- [ ] No fixed screenshot dates, artificial metrics or stock identities.
- [ ] Zero meters are empty; target/capacity calculations have safe denominators.
- [ ] Pipeline prerequisites are consistent across every entry point.
- [ ] Won deal creates one project; accepted quote conversion avoids duplicate invoices.
- [ ] Activity save does not double-count on retry.
- [ ] Allocation range semantics are explicit and cannot multiply hours accidentally.
- [ ] Financial totals, partial payments and statement balances reconcile.
- [ ] Filters, search, exports, forms, scheduling and any theme toggle actually work.
- [ ] Unconfigured integrations are not shown as successful or available.

## Interaction and presentation

- [ ] Desktop, tablet and mobile checked; no clipped forms or unreadable tables.
- [ ] Keyboard access, visible focus, dialog focus return and semantic labels checked.
- [ ] Normal text contrast at least 4.5:1; meaningful graphics and large text at least 3:1.
- [ ] Steppers and date pickers permit direct input; controls have accessible names.
- [ ] Loading, empty, partial, pending, failure and confirmed success states exist.
- [ ] Failed saves retain work; zero, long and unusually large values are handled.
- [ ] Reduced motion works without losing state feedback.

## Engineering and handoff

- [ ] Existing permissions and server authorization preserved.
- [ ] Required schema changes use migrations; no unreviewed destructive changes.
- [ ] Applicable build, type checks and domain tests pass.
- [ ] Browser console/network reviewed for concrete failures.
- [ ] Project knowledge and repository contain the design language and page specs.
- [ ] Added components are recorded in the map with states and validation.
- [ ] Remaining blocked integrations or uncertain domain definitions are explicitly recorded.
