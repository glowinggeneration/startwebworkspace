# Startweb Workspace

CRM, project delivery and invoicing for a single agency workspace. A deal
that closes becomes a tracked project; a project becomes an invoice — one
workspace-scoped source of truth from first call to final invoice.

This is Phase 0 (foundation) of a phased build — see the project's build
plan for the full roadmap. What exists so far: authentication and
onboarding, a workspace/RBAC data model, the authenticated app shell, and
every supplied UI component vendored in and cataloged for later phases.

## Development

The project uses TanStack Start, React, TypeScript, Vite and Supabase.
Dependencies are managed with [Bun](https://bun.sh) (`bun.lock` is the
lockfile of record).

```sh
bun install
bun run validate
```

`validate` runs the full test, build, typecheck and lint sequence.
Individual steps (`bun run test`, `bun run build`, `bun run typecheck`,
`bun run lint`) can be run on their own too.

```sh
bun run dev
```

`src/routeTree.gen.ts` is generated by TanStack Router. Do not hand-edit
it — running the Vite/TanStack build regenerates it from files under
`src/routes`.

## Environment and secrets

Copy `.env.example` to `.env` and fill in a Supabase project's connection
details. Never commit `.env` or real credentials. No Supabase project is
provisioned for this app yet — see `docs/build-standards/EXCEPTION_REGISTER.md`.

## Database migrations

Apply `supabase/migrations/` to a real Supabase project before testing any
authenticated flow end-to-end. `supabase/migrations/20260908000000_workspace_foundation.sql`
and `..._workspace_rls.sql` set up workspaces, membership/roles and RLS —
every later feature table follows the same pattern.
